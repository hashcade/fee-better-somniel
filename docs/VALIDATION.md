# Validation

## Current restructuring

Removed features must be absent from the compiled hook set, settings callbacks and startup writes, not merely hidden from the UI. Retain draw/meld, collection, facilities, ordinary-support settlement, shops, cooking, fishing, activity patches and standard-training quotas.

The host tests cover transaction planning, settings migration, fifteen-row ordering, batch-count step 10, independent persistence, native allowances and activity patches. Offline verification checks the target NSO Build ID/checksums and retained instruction windows.

Compiled AArch64 fixtures check startup, actual imported interfaces, native settings initialization/selection, retained callback registration, independent settings storage, polishing settlement, collection and facility navigation. These are modeled boundary checks, **not a running game**.

## Polishing regression

The pool and its used list are separate fixture objects. The pool's List-style header is empty, so treating it as a list performs no work. The correct list is stored only at +0x28, matching the independently verified native GetEnumerator instruction. Test cleaner selection, actual native bond cap methods, deduplication, dirt changes, per-Emblem/global records, disabled paths and repeated scans.

There must be no synthetic All Clean GodItem, manual polishing-list hook or automatic dialogue-skip hook.

## Inventory-free food regression

The food fixture executes the NSO-pinned Sommie list-stock branch, both full native BuildAttribute methods, the feeding decrement window, and the cooking selected-array settlement loop. First check native behavior, then use the words actually written by compiled plugin startup. Cover zero, one and multiple owned copies; ordinary ingredients and rare additions; missing recipe slots; the native confirm row; repeated cooking; and preservation of the selected array. External stock API calls are modeled. Offline NSO verification checks every fixture window before relying on it.

Host tests verify that one shared setting controls all eight ordinary-gift/food patch sites without changing the Repeat Cooking quota, global stock methods or the special-ingredient effect test. Compiled callbacks toggle the shared stock behavior, restore its original gates and costs, persist across item recreation, and roll back after a failed configuration save. Existing `gift_stock` values remain effective; missing values default on and explicitly disabled files restore native behavior at startup.

## Automatic Emblem conversation regression

The Emblem fixture executes the compiled Somniel hooks against NSO-pinned GodUnit wrappers, GodBondHolder.Get, GodBond.CanTalk, GetRelianceLevel, GetNextLevelExpInternal and LevelUp bodies. External pool/initialization, dictionary, growth-data, skill-acquisition and record-storage APIs are modeled. Cover ready C/B/A steps, insufficient EXP, already completed talks, chapter caps, native lazy bond initialization without extra EXP, cached null bonds, linked Emblem GIDs, equipped/absent/unavailable Emblems, duplicate entries, native aptitude updates, once-only idle scanning, menu re-entry, failed native advancement, disabled auto_support and non-Somniel contexts. No dialogue or reward UI may be called or bound.

## Automatic Sommie petting regression

The petting fixture executes the compiled automatic-arrival hooks, all fifteen settings callbacks, and NSO-pinned Mascot.AddPoint and GameUserData.set_PieceOfBond bodies. Discovery/completion, petting parameters, reward lookup, affection storage and native minimum helpers are modeled API boundaries. Cover undiscovered Sommie, missing reward data, independent enable/persistence, non-Somniel scenes, affection and wallet caps, cumulative acquisition using only the credited delta, and repeated scans after completion. No interaction or reward menu may be bound. Offline verification checks both complete cap bodies and the original Strok/GetBond/reward-settlement instruction windows.
